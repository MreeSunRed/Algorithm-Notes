# 缺失的第一个正数 (First Missing Positive)

> LeetCode 41 · 难度：困难 · 标签：数组、哈希表、原地算法

## 题目

给你一个未排序的整数数组 `nums`，请你找出其中没有出现的最小的正整数。

请你实现时间复杂度为 O(n) 并且只使用常数级别额外空间的解决方案。

```
输入: nums = [1,2,0]
输出: 3

输入: nums = [3,4,-1,1]
输出: 2

输入: nums = [7,8,9,11,12]
输出: 1
```

## 思路

### 先确定答案的范围

数组长度是 `n`，最多只有 `n` 个数。就算这 `n` 个数恰好是 `1..n`，缺失的第一个正数也只是 `n + 1`。

所以答案一定落在 **`[1, n + 1]`** 这个区间里。这个观察是后面所有解法的基石 —— 我们只需要关心这个范围内的正整数，负数、0、大于 `n` 的数都可以忽略。

### 思路一：哈希表（本仓库实现）

把数组中的正整数放进哈希表，然后从 1 开始逐个检查是否出现：

```python
d = {}
res = 1
for x in nums:
    if x <= 0:
        continue
    d[x] = True
    while res in d:
        res += 1
return res
```

**看起来是嵌套循环，为什么仍是 O(n)？**

`res` 只增不减，而且最大只会增加到 `n + 1`。内层 `while` 每执行一次，`res` 就永久前进 1；整个循环期间 `res` 总共最多前进 `n` 次。所以总工作量是 O(n)，不是 O(n²)。

**正确性**：`res` 始终表示「从 1 开始、已经连续出现过的最长前缀的下一个数」。扫完数组后，`res` 就是第一个没出现的正整数。

- 时间 O(n)
- 空间 O(n)

**缺点**：开了 O(n) 的哈希表，不满足题目「常数级别额外空间」的进阶要求。

### 思路二：把数组本身当作哈希表（O(1) 空间）

既然答案只在 `[1, n]` 里，而数组正好有 `n` 个位置，可以让数组**自己充当哈希表**：

> 数值 `x`（`1 <= x <= n`）应该放在下标 `x - 1` 的位置上。

也就是让 `nums[i] = i + 1`。做法是遍历每个位置，把「不属于这里」的数交换到它该去的位置：

```python
class Solution(object):
    def firstMissingPositive(self, nums):
        n = len(nums)
        for i in range(n):
            while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
                j = nums[i] - 1
                nums[i], nums[j] = nums[j], nums[i]

        for i in range(n):
            if nums[i] != i + 1:
                return i + 1
        return n + 1
```

**交换条件逐条解释：**

| 条件 | 作用 |
|------|------|
| `1 <= nums[i] <= n` | 超出范围的数不参与归位（它们不可能是 `[1,n]` 的答案） |
| `nums[nums[i] - 1] != nums[i]` | 目标位置已经放着正确的数，就不必再换；**这一条同时防止重复值导致死循环** |
| `while` 而不是 `if` | 一次交换后，换进来的新值可能仍然不属于当前位置，要继续处理 |

**为什么总共只有 O(n) 次交换？** 每次交换都会把 `nums[i]` 放到它的最终位置 `nums[i] - 1`，而这个位置之后不会再被换走（若再被换走，说明它又不在正确位置，与「已归位」矛盾）。每个数最多归位一次，总交换次数不超过 n。

归位完成后，从左往右找第一个 `nums[i] != i + 1` 的位置，答案就是 `i + 1`；如果全部匹配，说明 `1..n` 都出现了，答案是 `n + 1`。

以 `[3,4,-1,1]` 为例：

| 步骤 | 数组 |
|------|------|
| 初始 | `[3,4,-1,1]` |
| i=0：3 归位到下标 2 | `[-1,4,3,1]` |
| i=1：4 归位到下标 3 | `[-1,1,3,4]` |
| i=2：3 已在位，跳过 | `[-1,1,3,4]` |
| i=3：1 归位到下标 0 | `[1,-1,3,4]` |
| 扫描：下标 1 应为 2，实际是 -1 | 返回 `2` ✓ |

### 思路三：原地标记（另一种 O(1) 空间写法）

先保证所有数都是正数（把 `<= 0` 的数改成 `n + 1`），再把每个 `x ∈ [1,n]` 对应的 `nums[x-1]` 标记成负数。最后第一个不是负数的位置 `i` 对应答案 `i + 1`。

思路同样巧妙，但要处理 0、重复值和符号翻转，边界比循环归位更绕，实际面试中更推荐思路二。

## 复杂度

| 解法 | 时间 | 空间 | 特点 |
|------|:----:|:----:|------|
| 哈希表（本仓库） | O(n) | O(n) | 直观，`res` 单调递增保证线性 |
| 原地交换 | **O(n)** | **O(1)** | 满足进阶要求，面试首选 |
| 原地标记 | O(n) | O(1) | 可行，但边界处理更繁琐 |

## 代码

```python
class Solution(object):
    def firstMissingPositive(self, nums):
        """
        :type nums: List[int]
        :rtype: int
        """
        d = dict()
        res = 1
        for i in range(0, len(nums)):
            if nums[i] <= 0:
                continue
            d[nums[i]] = True
            while res in d:
                res = res + 1
        return res
```

## 易错点

- **忘记答案可能是 `n + 1`**：`[1,2,3]` 的答案是 4，不是 3。原地解法扫描完所有位置后要返回 `n + 1`。
- **内层 `while` 被误认为 O(n²)**：`res` 只增不减、上界是 `n + 1`，总迭代次数是 O(n)。这是本实现能通过的关键。
- **只跳过负数、忘了 0**：0 不是正整数，必须用 `nums[i] <= 0` 跳过。
- **原地交换时先索引后判范围**：`nums[nums[i] - 1]` 必须先保证 `1 <= nums[i] <= n`，否则负下标或越界会直接报错。Python 的负下标还会静默取到错误元素，更要小心。
- **漏掉重复值判断**：`[1,1]` 中第二个 1 的目标位置已经是 1，若继续交换会无限循环。条件 `nums[nums[i] - 1] != nums[i]` 必须保留。
- **`while` 写成 `if`**：交换进来的新值可能仍不在正确位置，需要继续交换，直到当前值归位或超出范围。
- **扫描时下标与值的关系写反**：正确值应满足 `nums[i] == i + 1`；返回的是 `i + 1`，不是 `i`。
- **原地解法修改了输入**：题目允许；若调用方后续还要用原数组，应先拷贝。
- **空数组**：题目保证 `1 <= n`；本仓库的哈希写法对空数组返回 1，也正确。
- **大于 `n` 的数**：它们不可能出现在答案范围 `[1, n]` 内，原地解法直接忽略；哈希解法把它们存进去也无害，只是浪费一点空间。

## 边界测试

| 输入 | 输出 | 说明 |
|------|:----:|------|
| `[1,2,0]` | `3` | 经典用例 |
| `[3,4,-1,1]` | `2` | 含负数和乱序 |
| `[7,8,9,11,12]` | `1` | 全部大于 n |
| `[1]` | `2` | 答案 `n + 1` |
| `[2]` | `1` | 1 缺失 |
| `[1,1]` | `2` | 重复值，不能死循环 |
| `[1,2,3]` | `4` | `1..n` 全部出现 |
| `[-1,-2]` | `1` | 全非正数 |
| `[2,1]` | `3` | 两个数都在，答案 3 |

# 两数之和 (Two Sum)

> LeetCode 1 · 难度：简单 · 标签：数组、哈希表

## 题目

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出**和为目标值** `target` 的那两个整数，并返回它们的数组下标。

你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

## 思路

### 暴力解

双重循环枚举所有 `(i, j)` 组合，判断 `nums[i] + nums[j] == target`。

- 时间 O(n²)，空间 O(1)

### 优化：哈希表

暴力解的浪费在于：对每个 `nums[i]`，我们都要重新扫一遍数组去找 `target - nums[i]`。

**关键转化**：与其「找搭档」，不如问「搭档有没有出现过、它在哪」。对当前元素 `num`，它需要的搭档是 `target - num` —— 这是一个**确定的、唯一的值**。

如果能把「值 → 下标」的查询做到 O(1)，内层循环就消失了。哈希表正好提供这个能力。

一次遍历，边扫边存：

| 步骤 | 动作 |
|------|------|
| 1 | 对 `nums[i]`，先查 `target - nums[i]` 是否已在字典中 |
| 2 | 命中 → 说明搭档出现在 `i` 之前，直接返回两个下标 |
| 3 | 未命中 → 把 `nums[i]: i` 存入字典，继续 |

**注意顺序：先查再存。**

这个顺序保证了：查询时字典里只有 `i` 之前的元素，所以搭档一定不是 `nums[i]` 自己 —— 「同一元素不能用两次」这条约束被结构性地满足了，不需要额外判断。

## 复杂度

- **时间 O(n)**：只遍历一次数组；字典的查找与插入均摊 O(1)
- **空间 O(n)**：最坏情况（答案在最后）字典需要存下前 n-1 个元素

典型的**空间换时间**：用 O(n) 空间把 O(n²) 时间压到 O(n)。

## 代码

```python
class Solution(object):
    def twoSum(self, nums, target):
        """
        :type nums: List[int]
        :type target: int
        :rtype: List[int]
        """
        keyv = dict()
        for i, num in enumerate(nums):
            if target - num in keyv:
                return [i, keyv[target - num]]
            keyv[num] = i
```

## 易错点

- **返回顺序**：`[i, keyv[target - num]]` 是「后出现的下标在前」。LeetCode 判定只比较下标集合，顺序无所谓；但若题目明确要求升序返回，需要改成 `sorted([i, keyv[target - num]])`。
- **重复元素**：`nums = [3, 3], target = 6` 时，第一轮存入 `{3: 0}`，第二轮 `i = 1` 查到 `3`，返回 `[1, 0]` —— 正确，且没用到同一个元素两次。
- **同一个元素用两次**：如果写成「先存后查」，`nums = [3, 3], target = 6` 时会返回 `[0, 0]`，错误。这就是「先查再存」的意义。
- **`in` 的语义**：`target - num in keyv` 判断的是**键**是否存在。别写成判断值。

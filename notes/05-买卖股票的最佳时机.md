# 买卖股票的最佳时机 (Best Time to Buy and Sell Stock)

> LeetCode 121 · 难度：简单 · 标签：数组、动态规划

## 题目

给定一个数组 `prices`，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。

你只能选择**某一天**买入这只股票，并选择在**未来的某个不同的日子**卖出。设计一个算法来计算你所能获取的最大利润。

返回你可以从这笔交易中获取的最大利润。如果你不能获取任何利润，返回 `0`。

```
输入: prices = [7,1,5,3,6,4]   输出: 5   （第 2 天买，第 5 天卖，6 - 1 = 5）
输入: prices = [7,6,4,3,1]     输出: 0   （一路下跌，不交易）
```

## 思路

### 暴力解

枚举买入日 `i` 和卖出日 `j`（`j > i`），计算 `prices[j] - prices[i]` 取最大值。

- 时间 O(n²)，空间 O(1)

### 优化：一次遍历，维护历史最低价

固定「卖出日」来看：如果我在第 `i` 天卖出，那么**最佳买入日一定是第 `i` 天之前价格最低的那一天**。

这句话的关键在于：买入日只可能在卖出日**之前**。所以扫描到第 `i` 天时，我需要的信息完全可以由「前缀」提供 —— 只要维护一个变量 `minNum`，记录 `prices[0..i-1]` 中的最小值即可。

于是每次迭代做两件事：

| 步骤 | 动作 |
|------|------|
| 1 | 用当前价格更新历史最低价 `minNum` |
| 2 | 计算「今天卖、历史最低价买」的利润，与 `maxNum` 打擂台 |

**为什么这样就够了？**

- 对每个卖出日，我们都试了它对应的最优买入日 → 不会漏掉最优解
- 历史最低价是**滚动**的，不需要重复扫描前缀 → 每个元素只访问一次

**和「最大子数组和」的关系**：把相邻两天的差价 `prices[i] - prices[i-1]` 看成新数组，本题的最大利润恰好等于这个**差分数组的最大连续子数组和**。也就是说，Kadane 算法同样能解这道题 —— 两者共享「沿途维护最优前缀」的同一个内核。

## 复杂度

- **时间 O(n)**：一次遍历，每轮 O(1) 操作
- **空间 O(1)**：只用了 `minNum`、`maxNum` 两个变量

## 代码

```python
class Solution(object):
    def maxProfit(self, prices):
        """
        :type prices: List[int]
        :rtype: int
        """
        maxNum = 0
        flag = False
        minNum = prices[0]
        for i in range(1, len(prices)):
            if minNum > prices[i]:minNum = prices[i]
            if (prices[i] - minNum) > maxNum:
                flag = True
                maxNum = prices[i] - minNum
        if flag:
            return maxNum
        return 0
```

这里的 `flag` 是多余的：`maxNum` 初始为 0，而利润永远不会是负数（`prices[i] - minNum >= 0`），所以不更新就返回 0 和 `flag = False` 返回 0 完全等价。去掉 `flag` 后逻辑更直接：

```python
maxNum = 0
minNum = prices[0]
for price in prices[1:]:
    minNum = min(minNum, price)
    maxNum = max(maxNum, price - minNum)
return maxNum
```

## 易错点

- **`minNum` 必须初始化成 `prices[0]`，不能是 0**：若初始化成 0，遇到 `[7,1,5,3,6,4]` 会把 0 当成历史最低价，利润全变成当天价格本身，答案错得离谱。`minNum` 的语义是「真实出现过的价格」，不是「利润下限」。
- **利润下限才是 0**：`maxNum` 初始化为 0，正好覆盖「全跌 → 不交易」的情况。若初始化为极小值，全跌用例会返回负数。
- **只能交易一次**：更新 `minNum` 和计算利润的顺序允许「当天买当天卖」（利润 0，不影响最大值），但**不允许先卖后买**。若题目允许多次交易，就是另一题（122），要用贪心或 DP。
- **不能排序**：`prices` 的下标就是时间顺序，排序会丢掉「买入必须在卖出之前」的约束。
- **空数组**：本题保证 `1 <= prices.length`，`prices[0]` 安全。若面试中不保证，需先加 `if not prices: return 0`。
- **单元素**：`[5]` 进入不了循环，直接返回 0 —— 正确，因为无法完成一次「买 + 卖」。

## 边界测试

| 输入 | 输出 | 说明 |
|------|:----:|------|
| `[7,1,5,3,6,4]` | `5` | 经典用例，第 2 天买、第 5 天卖 |
| `[7,6,4,3,1]` | `0` | **全跌** —— 不交易，返回 0 |
| `[1]` | `0` | 单元素，无法交易 |
| `[2,4,1]` | `2` | 最低价出现在最优卖出日之后，不能被误用 |
| `[3,2,6,5,0,3]` | `4` | 最低价在末尾附近，考验滚动更新 |

# 轮转数组 (Rotate Array)

> LeetCode 189 · 难度：中等 · 标签：数组、数学、双指针

## 题目

给定一个整数数组 `nums`，将数组中的元素向右轮转 `k` 个位置，其中 `k` 是非负数。

**要求原地修改**，不要返回新数组。

```
输入: nums = [1,2,3,4,5,6,7], k = 3
输出: [5,6,7,1,2,3,4]
解释:
向右轮转 1 步: [7,1,2,3,4,5,6]
向右轮转 2 步: [6,7,1,2,3,4,5]
向右轮转 3 步: [5,6,7,1,2,3,4]
```

## 思路

### 思路一：一步一步转（本仓库实现）

「向右轮转 1 步」就是把最后一个元素取出来放到最前面。重复 `k` 次即可。

用普通列表做这件事很吃亏：`insert(0, x)` 需要整体后移，单次 O(n)。换成 `collections.deque` 后，`pop()` 和 `appendleft()` 都是 O(1)，整体降到 O(n + k)：

```python
q = deque(nums)
for i in range(k):
    t = q.pop()
    q.appendleft(t)
nums[:] = q
```

**先取尾、再放头**的顺序不能反：`pop()` 拿到最后一个元素后，`appendleft` 才能把它放到最前面。

### 先取模：转 n 次等于没转

轮转具有周期性：转 `n` 次会回到原数组。所以先做

```python
k %= len(nums)
```

既能处理 `k > n` 的情况，也能避免 `k` 是 `n` 的倍数时白转一整圈。本仓库的循环写法在 `k` 很大时会做大量无用功，加上取模更稳妥。

### 思路二：三次反转（O(1) 空间，最优）

原地轮转有个非常优雅的解法：**整体反转 → 反转前 k 个 → 反转剩下 n-k 个**。

以 `[1,2,3,4,5,6,7]`、`k = 3` 为例：

| 步骤 | 结果 |
|------|------|
| 原数组 | `[1,2,3,4,5,6,7]` |
| 整体反转 | `[7,6,5,4,3,2,1]` |
| 反转前 3 个 | `[5,6,7,4,3,2,1]` |
| 反转后 4 个 | `[5,6,7,1,2,3,4]` ✓ |

**为什么有效？** 向右轮转的本质是「把末尾 k 个元素搬到前面」。整体反转先把末尾 k 个搬到了前面，但两部分的内部顺序都被打乱了（末尾 k 个反了，前面 n-k 个也反了）。再分别把这两段各自反转一次，内部顺序就恢复了。

```python
class Solution(object):
    def rotate(self, nums, k):
        n = len(nums)
        k %= n

        def reverse(left, right):
            while left < right:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
                right -= 1

        reverse(0, n - 1)      # 整体反转
        reverse(0, k - 1)      # 反转前 k 个
        reverse(k, n - 1)      # 反转剩余部分
```

- **时间 O(n)**：每个元素最多被交换两次
- **空间 O(1)**：只用了左右指针

### 思路三：切片拼接

如果允许 O(n) 额外空间，切片是最短写法：

```python
k %= len(nums)
nums[:] = nums[-k:] + nums[:-k]
```

注意 `k = 0` 时 `nums[-0:]` 是**整个数组**，`nums[:-0]` 是**空数组**，结果恰好还是原数组 —— 这个边界碰巧正确，但依赖了 Python 的切片语义，不如显式处理来得清晰。

## 复杂度

| 写法 | 时间 | 空间 | 备注 |
|------|:----:|:----:|------|
| deque 逐步旋转（本仓库） | O(n + k) | O(n) | 直观；建议先 `k %= n` |
| 三次反转 | **O(n)** | **O(1)** | 最优，原地交换 |
| 切片拼接 | O(n) | O(n) | 代码最短，但需要额外空间 |

## 代码

```python
from collections import deque
class Solution(object):
    def rotate(self, nums, k):
        """
        :type nums: List[int]
        :type k: int
        :rtype: None Do not return anything, modify nums in-place instead.
        """
        q = deque(nums)
        for i in range(k):
            t = q.pop()

            q.appendleft(t)
        nums[:] = q
```

## 易错点

- **`k` 可能大于等于 `n`**：`[1,2], k = 3` 的正确答案是 `[2,1]`（等价于转 1 次）。本仓库循环能算对，但会多转 `n` 的整数倍；先 `k %= n` 更高效，也避免 `k` 极大时的超时。
- **`k = 0`**：循环不执行，`nums[:] = q` 把原样写回，结果正确。三次反转写法中 `reverse(0, -1)` 是空区间（`left < right` 不成立），也不会出错。
- **原地修改必须用 `nums[:] = ...`**：写成 `nums = q` 只是把局部变量指向了新对象，调用方的数组不会变，LeetCode 会判错。
- **不要 `return nums`**：题目要求原地修改、返回 `None`。虽然返回数组通常也能过，但不符合函数签名。
- **方向别搞反**：`k = 1` 是把**最后一个**元素移到最前（右旋），不是把第一个移到末尾（左旋）。
- **空数组**：LeetCode 保证 `n >= 1`，本实现不需要处理；若允许空数组，`k %= 0` 会触发 `ZeroDivisionError`，需要特判。
- **deque 的空间开销**：`deque(nums)` 复制了一份数组，空间是 O(n)，不满足题目「尽量用 O(1) 空间」的进阶要求。面试可以先说这个直观解法，再给出三次反转。
- **切片版的 `-0` 陷阱**：`nums[-0:]` 等于 `nums[0:]`（整个数组），不是空数组。`k = 0` 时结果碰巧正确，但换成别的语言（如 C++ 的迭代器）就不一定，最好显式处理 `k == 0`。

## 边界测试

| 输入 | 输出 | 说明 |
|------|------|------|
| `[1,2,3,4,5,6,7], k=3` | `[5,6,7,1,2,3,4]` | 经典用例 |
| `[-1,-100,3,99], k=2` | `[3,99,-1,-100]` | 含负数 |
| `[1], k=0` | `[1]` | 单元素、不轮转 |
| `[1], k=5` | `[1]` | `k > n`，取模后为 0 |
| `[1,2], k=3` | `[2,1]` | `k > n`，等价于转 1 次 |
| `[1,2,3,4], k=4` | `[1,2,3,4]` | `k = n`，回到原样 |
| `[1,2,3], k=0` | `[1,2,3]` | `k = 0` |

# 排序链表 (Sort List)

> LeetCode 148 · 难度：中等 · 标签：链表、归并排序、分治

## 题目

给你链表的头结点 `head`，请将其按**升序**排列并返回排序后的链表。

```
输入: head = [4,2,1,3]
输出: [1,2,3,4]

输入: head = [-1,5,3,4,0]
输出: [-1,0,3,4,5]

输入: head = []
输出: []
```

**进阶**：你可以在 `O(n log n)` 时间复杂度和常数额外空间复杂度下解决本题吗？

## 思路

### 为什么选归并排序

数组排序的常客快速排序在链表上并不合适：

- 链表无法 O(1) 随机访问，快排的分区需要额外遍历
- 快排最坏 O(n²)，且递归深度不稳定

归并排序天然适合链表：

- **找中点**用快慢指针，O(n)
- **合并两个有序链表**只需要重接指针，不需要额外数组
- 时间复杂度稳定 O(n log n)，且是稳定排序

### 本仓库实现：自顶向下归并

```python
if head is None or head.next is None:
    return head
first = head
second = head.next
while second and second.next:
    first = first.next
    second = second.next.next
mid = first.next
first.next = None
left = self.sortList(head)
right = self.sortList(mid)
return self.Merge(left, right)
```

**找中点并断开**：

- `second` 从 `head.next` 出发，比 `first` 快一倍
- 循环结束时 `first` 停在左半段的最后一个节点，`mid = first.next` 是右半段的头
- `first.next = None` 把两段彻底断开，避免递归时重复处理

**为什么 `second` 从 `head.next` 开始？** 这是为了处理只有两个节点的情况：

- 若 `first = second = head`，两节点链表循环后 `mid` 会等于 `head`，左半段仍是原链表，递归无法缩小规模，直接无限递归
- 从 `head.next` 出发，两节点时循环不执行，`mid = head.next`，正好拆成 `[head]` 和 `[head.next]` 两个单节点

以 `[4,2,1,3]` 为例：

| 步骤 | 左半段 | 右半段 | 合并结果 |
|------|--------|--------|----------|
| 第一次拆分 | `[4,2]` | `[1,3]` | — |
| 递归排序 | `[2,4]` | `[1,3]` | `[1,2,3,4]` |

**合并**：

```python
res = ListNode(0)      # 哑节点，避免单独处理第一个节点
ls = res
while root1 and root2:
    if root1.val <= root2.val:
        res.next = root1
        root1 = root1.next
    else:
        res.next = root2
        root2 = root2.next
    res = res.next
res.next = root1 if root1 else root2
return ls.next
```

- 用 `<=` 保证稳定性：相等时优先取左半段
- 某一段耗尽后，把另一段整段接上即可
- 返回 `ls.next`，跳过哑节点

### 其他写法

- **自底向上归并**：不递归，按步长 1、2、4、8……依次合并相邻两段，可以做到 O(1) 额外空间，满足进阶要求。代码更长，但适合面试追问。
- **转数组排序**：把节点值放进数组，排序后写回链表。时间 O(n log n)，空间 O(n)，实现最简单，但不满足进阶的空间要求，也不是真正的节点重排。
- **插入排序**：147 题的解法，链表上最坏 O(n²)，数据量大时会超时。

## 复杂度

- **时间 O(n log n)**：每层合并遍历 O(n)，共 log n 层
- **空间 O(log n)**（本实现）：递归栈深度；递归之外的临时空间为 O(1)
- **进阶 O(1) 空间**：需要改写成自底向上归并

## 代码

```python
# Definition for singly-linked list.
class ListNode(object):
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


class Solution(object):
    def sortList(self, head):
        """
        :type head: Optional[ListNode]
        :rtype: Optional[ListNode]
        """
        if head is None or head.next is None:
            return head
        first = head
        second = head.next
        while second and second.next:
            first = first.next
            second = second.next.next
        mid = first.next
        first.next = None
        left = self.sortList(head)
        right = self.sortList(mid)
        return self.Merge(left, right)

    def Merge(self, root1, root2):
        res = ListNode(0)
        ls = res
        while root1 and root2:
            if root1.val <= root2.val:
                res.next = root1
                root1 = root1.next
                res = res.next
            else:
                res.next = root2
                root2 = root2.next
                res = res.next
        if root1:
            res.next = root1
        else:
            res.next = root2
        return ls.next
```

## 易错点

- **快慢指针起点相同**：两节点时会拆不出两段，导致无限递归。必须让 `second` 从 `head.next` 开始，或改用「先让 `second` 走一步」的写法。
- **忘记断开 `first.next = None`**：左半段仍然连着右半段，递归会重复处理同一批节点，可能死循环或结果错误。
- **递归出口遗漏单节点**：`head.next is None` 必须返回，否则单节点还会继续找中点、拆分。
- **合并时忘记哑节点**：直接处理第一个节点会让代码充满分支；用 `ListNode(0)` 简化，最后返回 `dummy.next`。
- **合并后返回错节点**：要返回 `ls.next`，不是哑节点本身，也不是 `res`（它已经走到尾部）。
- **用 `<` 而不是 `<=`**：相等元素会优先取右半段，破坏稳定性。本题只要求有序，但保持稳定是好习惯。
- **只交换 `val` 不重接节点**：题目要求排序链表；若外部持有节点引用，只改值会破坏语义。本实现重接的是节点本身。
- **空链表 / 单节点**：递归出口已经覆盖，直接返回原头。
- **三节点链表**：`second` 走到末尾后 `first` 停在第二个节点，拆成 `[1,2]` 和 `[3]`，不会漏节点。
- **递归深度**：深度为 O(log n)，即使 n = 5×10⁴ 也只有约 16 层，不会触发递归上限。

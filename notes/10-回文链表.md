# 回文链表 (Palindrome Linked List)

> LeetCode 234 · 难度：简单 · 标签：链表、双指针、栈、递归

## 题目

给你一个单链表的头节点 `head`，请你判断该链表是否为回文链表。如果是，返回 `true`；否则，返回 `false`。

```
输入: 1 → 2 → 2 → 1
输出: true

输入: 1 → 2
输出: false
```

## 思路

链表的痛点是**只能单向遍历**，没法像数组那样从两端同时向中间靠拢。所有解法本质上都在解决同一个问题：**如何获得「从后往前」的访问能力**。

### 思路一：转成数组（本仓库实现）

先把所有值抄进列表，问题立刻退化成「判断数组是否回文」：

```python
nums = []
while head != None:
    nums.append(head.val)
    head = head.next

for i, val in enumerate(nums):
    if val != nums[-1 * (i + 1)]:   # 与对称位置比较
        return False
    if i >= len(nums) / 2:          # 走到中线就停
        return True
```

`nums[-1 * (i + 1)]` 就是 `nums[-i-1]`：`i = 0` 时取最后一个，`i = 1` 时取倒数第二个，正好和正着数的 `nums[i]` 对称。

**为什么到中线就能返回 `True`？** 对称比较是一对一对做的，走到中线说明所有对都配上了，后半段与前半段必然一致，没必要再重复比较一遍。

- 时间 O(n)，空间 O(n)

**优点**：直观、好写、不容易错。
**缺点**：额外开了 O(n) 空间，不满足「能否用 O(1) 空间解决」的进阶要求。

### 思路二：快慢指针 + 反转后半段（O(1) 空间）

既然链表不能倒着走，那就**把后半段反过来**，就能从两端向中间比较了：

1. **快慢指针找中点**：`slow` 每步走 1，`fast` 每步走 2。`fast` 到头时，`slow` 正好在中点（奇数长度）或后半段的起点（偶数长度）
2. **反转后半段**：复用 [206. 反转链表](09-反转链表.md) 的迭代写法
3. **双指针比较**：`p1` 从头出发，`p2` 从反转后的后半段出发，逐个比较值
4. （可选）**恢复链表**：把后半段再反转回去，保持原结构

```python
class Solution(object):
    def isPalindrome(self, head):
        # 1. 找中点
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        # 2. 反转后半段
        prev = None
        while slow:
            nxt = slow.next
            slow.next = prev
            prev = slow
            slow = nxt

        # 3. 比较
        p1, p2 = head, prev
        while p2:
            if p1.val != p2.val:
                return False
            p1, p2 = p1.next, p2.next
        return True
```

- 时间 O(n)，空间 **O(1)**

**奇数长度为什么也能直接比较？** 反转后 `p2` 指向原链表的最后一个节点，`p1` 从原头开始；中间的节点会与自己做比较，天然相等，不影响结论。

### 思路三：栈

把前半段压栈，再与后半段逐个弹出比较。时间 O(n)、空间 O(n)。思路直观，但和转数组没有本质区别，面试中通常作为过渡方案提及。

## 复杂度

| 解法 | 时间 | 空间 | 特点 |
|------|:----:|:----:|------|
| 转数组（本仓库） | O(n) | O(n) | 最简单，先保证正确 |
| 快慢指针 + 反转 | O(n) | **O(1)** | 最优，面试加分项 |
| 栈 | O(n) | O(n) | 直观，但无空间优势 |

## 代码

```python
class Solution(object):
    def isPalindrome(self, head):
        """
        :type head: Optional[ListNode]
        :rtype: bool
        """
        nums = []
        while head != None:
            nums.append(head.val)
            head = head.next
        for i, val in enumerate(nums):
            if val != nums[-1 * (i + 1)]:
                return False
            if i >= len(nums) / 2:
                return True
        return True
```

## 易错点

- **末尾的 `return` 不能留空（原代码的真实 bug）**：单节点 `[1]` 时 `i = 0`，而 `0 >= 1/2`（`0 >= 0.5`）为假，循环直接结束，执行到末尾的 `return`，返回 `None`。LeetCode 把 `None` 当假值，单节点用例会被判错。末尾必须写 `return True`。这个 bug 很容易被「只测多节点用例」漏掉，边界测试里的 `[1]` 就是专门抓它的。
- **`len(nums) / 2` 是浮点除法**：Python 3 中结果是 `float`，与整数 `i` 比较没有问题，但语义上写成 `len(nums) // 2` 更清晰。注意边界：偶数长度时 `i == n/2` 恰好在中线右侧第一个元素，返回 `True` 是正确的；奇数长度时会在中点后一个位置返回。
- **中线判断放在比较之后**：必须先比较当前这对，再判断是否走到中线；写反会漏掉中间那一对。
- **对称下标别写错**：`nums[-1 * (i + 1)]` 等价于 `nums[-i-1]`，也等价于 `nums[len(nums) - 1 - i]`。不要写成 `nums[-i]`（`i = 0` 时越界取到第一个元素）。
- **空链表**：LeetCode 保证至少一个节点。若要健壮处理，应在开头加 `if not head: return True`。
- **O(1) 解法会修改链表**：反转后半段改变了 `next` 指针。LeetCode 不检查原结构，但若调用方之后还要用这条链表，应把后半段再反转恢复。
- **快慢指针的循环条件**：`while fast and fast.next` 两个条件都不能少，否则 `fast.next.next` 可能对 `None` 取属性。
- **只比较值，不比较节点**：回文判断依据是 `val`，不是节点身份。

## 边界测试

| 输入 | 输出 | 说明 |
|------|:----:|------|
| `[1,2,2,1]` | `true` | 偶数长度回文 |
| `[1,2,3,2,1]` | `true` | 奇数长度回文，中间节点与自己比较 |
| `[1,2]` | `false` | 偶数长度非回文 |
| `[1]` | `true` | 单节点 |
| `[1,1,2,1]` | `false` | 前半对称、后半破坏 |
| `[1,2,1,1]` | `false` | 镜像位置不匹配 |

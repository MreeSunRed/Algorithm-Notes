# 除了自身以外数组的乘积 (Product of Array Except Self)

> LeetCode 238 · 难度：中等 · 标签：数组、前缀和

## 题目

给你一个整数数组 `nums`，返回数组 `answer`，其中 `answer[i]` 等于 `nums` 中除 `nums[i]` 之外其余各元素的乘积。

题目数据**保证**数组 `nums` 之中任意元素的全部前缀元素和后缀的乘积都在 32 位整数范围内。

**请不要使用除法**，且在 O(n) 时间复杂度内完成此题。

```
输入: nums = [1,2,3,4]
输出: [24,12,8,6]
解释:
answer[0] = 2*3*4 = 24
answer[1] = 1*3*4 = 12
answer[2] = 1*2*4 = 8
answer[3] = 1*2*3 = 6
```

## 思路

### 暴力解

对每个下标 `i`，再遍历一遍数组，把除 `nums[i]` 外的数乘起来。

- 时间 O(n²)，空间 O(1)（不计输出）

### 为什么不能直接「总乘积 / nums[i]」

如果不考虑题目限制，最直接的做法是算出所有元素的乘积 `total`，再令 `answer[i] = total / nums[i]`。

问题在于 **`nums` 中可能有 0**：

- 一个 0：`total = 0`，除 0 位置外其他位置都会得到 `0 / nums[i] = 0`，全部错误
- 多个 0：几乎所有答案都是 0，但除法会直接触发 `ZeroDivisionError`

即使特判 0 的数量，也会把代码写得很绕。更好的思路是**完全绕开除法**。

### 前缀积 × 后缀积

把 `answer[i]` 拆成两部分：

```
answer[i] = (nums[0] × nums[1] × … × nums[i-1]) × (nums[i+1] × … × nums[n-1])
             └──────────── 左侧前缀积 ────────────┘   └──────────── 右侧后缀积 ────────────┘
```

也就是说，**除自身以外的乘积 = 左边所有数的乘积 × 右边所有数的乘积**。

于是可以分两趟：

1. **从左往右**：`res[i]` 先存 `nums[0..i-1]` 的乘积
2. **从右往左**：把 `nums[i+1..n-1]` 的乘积乘进 `res[i]`

两趟都只用一重循环，并且可以复用输出数组，不需要额外的前缀/后缀数组。

### 本仓库实现

```python
res = [1] * len(nums)

left = nums[0]
for i in range(1, len(nums)):
    res[i] *= left      # res[i] = nums[0] * ... * nums[i-1]
    left *= nums[i]     # 更新前缀积，供下一个位置使用

right = nums[-1]
for i in range(len(nums) - 2, -1, -1):
    res[i] *= right     # 再乘上 nums[i+1] * ... * nums[n-1]
    right *= nums[i]    # 更新后缀积
```

以 `[1,2,3,4]` 为例：

| 阶段 | `res` |
|------|-------|
| 初始化 | `[1, 1, 1, 1]` |
| 第一趟结束后 | `[1, 1, 2, 6]`（各位置左侧乘积） |
| 第二趟结束后 | `[24, 12, 8, 6]` ✓ |

**注意 `res[0]` 和 `res[n-1]`：**

- `res[0]` 左侧没有元素，前缀积视为 1，第一趟不处理它
- `res[n-1]` 右侧没有元素，后缀积视为 1，第二趟从 `n-2` 开始

这正是初始化 `[1] * n` 的意义。

### 为什么能避开 0

前缀/后缀积是**纯乘法**，0 会自然地进入乘积：

- 只有一个 0：含 0 的那一侧乘积为 0，0 位置本身的前缀和后缀都不含 0，答案正确
- 有多个 0：所有包含 0 的乘积都是 0，结果同样正确

不需要任何特判。

## 复杂度

- **时间 O(n)**：两趟线性扫描
- **空间 O(1)**（不计输出数组）：只用了 `left`、`right` 两个变量

如果额外开前缀、后缀两个数组，空间是 O(n)，本题的进阶要求正是把空间压到 O(1)。

## 代码

```python
class Solution(object):
    def productExceptSelf(self, nums):
        """
        :type nums: List[int]
        :rtype: List[int]
        """
        res = [1] * len(nums)
        left = nums[0]
        for i in range(1, len(nums)):
            res[i] *= left
            left *= nums[i]
        right = nums[-1]
        for i in range(len(nums) - 2, -1, -1):
            res[i] *= right
            right *= nums[i]
        return res
```

## 易错点

- **用除法**：只要有一个 0 就会出错，多个 0 还会除零。前缀/后缀积不需要特判。
- **两趟的边界**：第一趟从 `i = 1` 开始（`res[0]` 左侧为空，保持 1）；第二趟从 `i = n-2` 开始（`res[n-1]` 右侧为空）。
- **`res[i] *= left` 与 `left *= nums[i]` 的顺序**：必须先乘 `res[i]`（此时 `left` 不含 `nums[i]`），再更新 `left`。反过来会把 `nums[i]` 自己乘进去。
- **后缀方向同理**：先把当前后缀积 `right` 乘进 `res[i]`，再让 `right *= nums[i]`。
- **`left` / `right` 的初始化**：`left = nums[0]`、`right = nums[-1]`，不能初始化成 1 后再少走一步，容易把边界绕错。
- **`n = 1`**：两趟循环都不执行，返回 `[1]`，正确 —— 除自身外没有元素，空积为 1。
- **`n = 0`**：LeetCode 保证 `2 <= nums.length`，本实现若遇到空数组会在 `nums[0]` 处报 `IndexError`；工程代码可加空数组保护。
- **输出数组的空间算不算 O(1)**：题目通常不把返回值计入额外空间，所以本解法满足「O(1) 额外空间」。
- **不要修改原数组**：`res` 是新建的，`nums` 保持不变；若直接在 `nums` 上改会破坏后续计算。
- **整数溢出**：Python 整数不会溢出；C++/Java 需要注意用 `long`，尽管题目保证结果在 32 位范围内，中间乘积也在此范围内。

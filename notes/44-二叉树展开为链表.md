# 二叉树展开为链表 (Flatten Binary Tree to Linked List)

> LeetCode 114 · 难度：中等 · 标签：树、前序遍历、指针操作

## 题目

给你二叉树的根结点 `root`，请你将它展开为一个单链表：

- 展开后的单链表同样使用 `TreeNode`，`right` 子指针指向链表中的下一个结点
- 左子指针 `left` 始终为 `null`
- 展开后的顺序必须与二叉树的**前序遍历**顺序一致
- **原地修改**，不要返回新链表

```
输入: root = [1,2,5,3,4,null,6]
输出: [1,null,2,null,3,null,4,null,5,null,6]

输入: root = []
输出: []

输入: root = [0]
输出: [0]
```

经典用例的树形：

```
      1
     / \
    2   5
   / \   \
  3   4   6
```

前序遍历为 `1 → 2 → 3 → 4 → 5 → 6`，展开后每个节点只保留 `right` 指针。

## 思路

### 核心观察

题目要求的顺序就是前序遍历。最直接的想法是：

1. 先按前序遍历把所有节点收集起来
2. 再按顺序把它们用 `right` 指针串起来，同时把 `left` 置空

难点在于「原地修改」：串链表时会覆盖节点原有的 `left` / `right`，如果还没访问到被覆盖的子树，就会丢失节点。

### 本仓库实现：前序收集 + 倒序重接

第一段递归只做一件事：按前序把节点放进列表 `s`，此时**不改任何指针**，所以不会丢节点。

```python
s.append(root)
preorder(root.left)
preorder(root.right)
```

第二段从列表尾部开始重建：

```python
root = s.pop()
while s != []:
    cur_node = s.pop()
    cur_node.left = None
    cur_node.right = root
    root = cur_node
```

**为什么倒着接？** 从最后一个节点开始，每次取出的节点都指向「已经接好的后缀链表」。这样每个节点的 `right` 都指向一条最终形态的链，不需要关心它原来的右子树有没有处理完——因为在第一段里所有节点都已经被保存下来了。

以经典用例为例，`s = [1, 2, 3, 4, 5, 6]`：

| 步骤 | 取出 | 操作 | 当前链 |
|:----:|:----:|------|--------|
| 1 | 6 | `root = 6` | `6` |
| 2 | 5 | `5.left = None`，`5.right = 6` | `5 → 6` |
| 3 | 4 | `4.left = None`，`4.right = 5` | `4 → 5 → 6` |
| 4 | 3 | `3.left = None`，`3.right = 4` | `3 → 4 → 5 → 6` |
| 5 | 2 | `2.left = None`，`2.right = 3` | `2 → 3 → 4 → 5 → 6` |
| 6 | 1 | `1.left = None`，`1.right = 2` | `1 → 2 → 3 → 4 → 5 → 6` |

注意最后一行：原树的根节点 `1` 是前序第一个节点，所以展开后的头节点仍然是它，调用方持有的 `root` 引用依然有效。代码里的 `root = s.pop()` 只是把局部变量当作工作指针，并不会改变调用方的根引用——但因为节点本身被原地修改，结果是对的。

### 其他写法

- **前序收集 + 正序重接**：用一个 `prev` 指针顺序遍历列表，`prev.right = cur`、`prev.left = None`。同样需要先收集，否则会丢子树。
- **迭代前序 + 边遍历边改**：用栈模拟前序，出栈时立刻把 `prev.right` 指向当前节点。栈里保存的是待访问节点，所以覆盖指针是安全的，额外空间 O(h)。
- **O(1) 空间的前驱拼接法**（推荐了解）：

  ```python
  cur = root
  while cur:
      if cur.left:
          pre = cur.left
          while pre.right:
              pre = pre.right
          pre.right = cur.right   # 左子树最后访问的节点接上原右子树
          cur.right = cur.left    # 左子树整体移到右边
          cur.left = None
      cur = cur.right
  ```

  前序遍历中，`cur` 之后紧跟着的是左子树；左子树最后被访问的节点是它的**最右节点**。把原右子树挂到这个最右节点后面，再把左子树移到右边，就完成了一个节点的展开。每个节点只被访问常数次，总时间 O(n)，额外空间 O(1)。

## 复杂度

| 写法 | 时间 | 空间 |
|------|:----:|:----:|
| 前序收集 + 倒序重接（本仓库） | O(n) | O(n) 列表 + O(h) 递归栈 |
| 迭代前序 | O(n) | O(h) 栈 |
| 前驱拼接 | O(n) | O(1) |

其中 `h` 为树高；最坏情况（链状树）`h = n`。

## 代码

```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right


class Solution(object):
    def flatten(self, root):
        """
        :type root: Optional[TreeNode]
        :rtype: None Do not return anything, modify root in-place instead.
        """
        s = []

        def preorder(root):
            if root == None:
                return
            # visit
            s.append(root)
            preorder(root.left)
            preorder(root.right)

        preorder(root)
        if s == []:
            return
        root = s.pop()
        while s != []:
            cur_node = s.pop()
            cur_node.left = None
            cur_node.right = root
            root = cur_node
```

## 易错点

- **只改 `right`，忘记把 `left` 置空**：题目要求展开后所有节点的左指针都是 `null`。
- **展开顺序写错**：必须是**前序**（根 → 左 → 右），不是中序或层序。左子树整体排在右子树前面。
- **边遍历边改指针导致丢子树**：如果先写 `cur.right = cur.left` 再访问原来的右子树，右子树入口已经没了。要么先保存，要么先收集所有节点。
- **返回值**：题目要求原地修改，返回 `None`。不要 `return root`，也不要重新构造一棵树返回。
- **误以为 `root = s.pop()` 改坏了根节点**：这里 `root` 只是局部工作变量；展开后的头节点是前序第一个节点，仍是被调用方传入的原根节点。
- **空树**：`preorder(None)` 什么也不做，`s == []` 时直接返回，不会执行 `pop`。
- **单节点**：`s` 只有一个元素，`pop` 后 `while` 不执行，节点保持原样（本来就是叶子，`left` 为空）。
- **递归深度**：本题节点数上限为 2000，链状树递归深度可达 2000，超过 Python 默认递归上限（约 1000）会抛 `RecursionError`。链表化的树、竞赛评测的极端数据要改用迭代写法。
- **把所有节点按层序收集**：`level_order` / BFS 得到的顺序与题目要求不符。
- **以为原右子树会被保留**：展开后原来的树形结构完全消失，只剩一条 `right` 链。

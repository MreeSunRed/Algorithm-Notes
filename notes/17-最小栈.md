# 最小栈 (Min Stack)

> LeetCode 155 · 难度：中等 · 标签：栈、设计

## 题目

设计一个支持 `push`、`pop`、`top` 操作，并能在 **O(1)** 时间内检索到最小元素的栈。

实现 `MinStack` 类：

- `MinStack()` 初始化堆栈对象
- `void push(int val)` 将元素 `val` 推入堆栈
- `void pop()` 删除堆栈顶部的元素
- `int top()` 获取堆栈顶部的元素
- `int getMin()` 获取堆栈中的最小元素

```
输入:
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

输出:
[null,null,null,null,-3,null,0,-2]
```

## 思路

### 难点在哪

`push`、`pop`、`top` 本来都是 O(1)。真正的问题是 `getMin`：

- 如果每次扫描一遍栈，`getMin` 就是 O(n)
- 如果只用一个变量 `self.min` 记录最小值，`pop` 掉当前最小值后，**无法知道第二小是谁** —— 除非重新扫描

所以关键不是「记住最小值」，而是「记住**每个时刻**的最小值」，让 `pop` 之后能立刻恢复上一个状态。

### 本仓库实现：每个节点快照当前最小值

每个栈节点不只存 `val`，还存一个 `mins`：**这个节点入栈时，整个栈的最小值**。

`push` 时：

```
新节点的 mins = min(新值, 原栈顶的 mins)
栈为空时      mins = 新值
```

于是：

| 操作 | 实现 |
|------|------|
| `top()` | 返回栈顶节点的 `val` |
| `getMin()` | 返回栈顶节点的 `mins` —— 它就是当前整个栈的最小值 |
| `pop()` | 直接弹出栈顶；前一个节点的 `mins` 天然是剩余栈的最小值 |

**为什么 `pop` 后最小值能自动恢复？** 因为每个节点都保存了「包含自己在内、到栈底为止」的最小值。弹掉栈顶后，新的栈顶节点在入栈时就已经记录好了它那个时刻的最小值 —— 这正是剩余栈的最小值。不需要重新计算。

以 `push(-2), push(0), push(-3)` 为例：

| 栈（底 → 顶） | 节点 `(val, mins)` |
|---------------|---------------------|
| 初始 | 空 |
| push(-2) | `(-2, -2)` |
| push(0) | `(-2, -2), (0, -2)` |
| push(-3) | `(-2, -2), (0, -2), (-3, -3)` |
| getMin() | 栈顶 `mins = -3` ✓ |
| pop() | `(-2, -2), (0, -2)` |
| getMin() | 栈顶 `mins = -2` ✓ |

### 等价写法一：两个栈

一个数据栈存值，一个辅助栈同步存「当前最小值」：

```python
class MinStack(object):
    def __init__(self):
        self.stack = []
        self.mins = []

    def push(self, val):
        self.stack.append(val)
        self.mins.append(min(val, self.mins[-1]) if self.mins else val)

    def pop(self):
        self.stack.pop()
        self.mins.pop()

    def top(self):
        return self.stack[-1]

    def getMin(self):
        return self.mins[-1]
```

两个栈必须**同步进出**：每 push 一次辅助栈也 push，每 pop 一次辅助栈也 pop。这样辅助栈顶永远对应当前栈的最小值。

### 等价写法二：栈里直接存元组

不定义 `Node` 类，直接把 `(val, 当前最小值)` 塞进普通列表：

```python
def push(self, val):
    cur_min = min(val, self.stack[-1][1]) if self.stack else val
    self.stack.append((val, cur_min))
```

和本仓库的 `Node` 方案完全等价，只是用元组代替了对象。`Node` 可读性更好，元组更轻量。

## 复杂度

- **时间 O(1)**：`push` / `pop` / `top` / `getMin` 都只访问栈顶或做一次比较
- **空间 O(n)**：每个元素额外保存一个最小值；`n` 为栈中元素个数

## 代码

```python
class MinStack(object):

    class Node:
        def __init__(self, val=None, mins=None):
            self.val = val
            self.mins = mins

    def __init__(self):
        self.stack = []
        self.node = MinStack.Node()
        self.node.mins = 2**31 - 1

    def push(self, value):
        """
        :type value: int
        :rtype: None
        """
        if not self.stack:
            t = MinStack.Node(val=value, mins=value)
            self.stack.append(t)
            return
        top = self.stack[-1]
        t = MinStack.Node(val=value, mins=value)
        if t.mins > top.mins:
            t.mins = top.mins
        self.stack.append(t)

    def pop(self):
        """
        :rtype: None
        """
        self.stack.pop().val

    def top(self):
        """
        :rtype: int
        """
        return self.stack[-1].val

    def getMin(self):
        """
        :rtype: int
        """
        return self.stack[-1].mins
```

## 易错点

- **只用一个 `self.min` 变量**：`push` 时更新很容易，但 `pop` 掉最小值后就无法恢复上一个最小值。必须为每个元素保存历史最小值，或用辅助栈。
- **辅助栈不同步**：如果只在「新值更小」时才往辅助栈 push，`pop` 时却无条件 pop，两个栈就会错位。要么同步进出，要么在 pop 时判断弹出的值是否等于辅助栈顶。
- **重复最小值**：`push(1), push(1)` 后 pop 一次，`getMin` 仍应是 1。每个节点存快照的写法天然正确；用辅助栈时要注意相等值也要入栈（用 `<=` 而不是 `<`）。
- **空栈操作**：题目保证 `pop` / `top` / `getMin` 只在栈非空时调用。若要在工程中健壮处理，应加判空并抛出明确异常。
- **`self.node` 是死代码**：`__init__` 里创建了一个 `Node` 并把 `mins` 设为 `2**31-1`，但之后从未使用。`push` 对空栈有单独分支，因此不影响正确性。可以直接删掉这三行，或把它真正当作哨兵使用。
- **哨兵值的隐患**：`2**31-1` 恰好是 LeetCode 值域的上界，作为「正无穷」没问题；但如果元素可能超过这个上界，拿它当初始最小值就会出错。空栈单独处理是更稳妥的做法。
- **`pop()` 的返回值**：LeetCode 要求原地弹出、返回 `None`。本实现 `self.stack.pop().val` 只是取出值后丢弃，符合要求；不要改成返回被弹出的值。
- **`MinStack.Node` 的引用方式**：在方法内部通过类名 `MinStack.Node` 创建节点是可行的；写 `self.Node` 也可以，但不要写成未定义的 `Node`（会触发 `NameError`）。
- **缩进**：嵌套类和方法都属于 `MinStack` 类体，缩进层级要一致。原文件使用了较宽的非标准缩进，逻辑没问题，但按 PEP 8 统一为 4 空格更易读。
- **`top` 与 `getMin` 的区别**：`top` 是最后入栈的值，`getMin` 是当前栈的最小值，二者只在特定时刻相等。

## 边界测试

| 操作序列 | 预期结果 | 说明 |
|----------|----------|------|
| push(-2), push(0), push(-3), getMin() | `-3` | 当前最小在栈顶 |
| 接上：pop(), top(), getMin() | `0`, `-2` | 弹出最小值后恢复上一个状态 |
| push(0), push(0), getMin() | `0` | 重复最小值 |
| 接上：pop(), getMin() | `0` | 弹出一个 0 后最小仍是 0 |
| push(5), top(), getMin() | `5`, `5` | 单元素 |
| push(2), push(1), pop(), getMin() | `2` | 弹出更小值后回退 |
| push(-1), push(-2), push(-3), pop(), getMin() | `-2` | 连续负值，排除哨兵干扰 |

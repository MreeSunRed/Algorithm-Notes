# 二叉树的中序遍历 (Binary Tree Inorder Traversal)

> LeetCode 94 · 难度：简单 · 标签：树、深度优先搜索、二叉树

## 题目

给定一个二叉树的根节点 `root`，返回它的**中序遍历**结果。

中序遍历的顺序是：**左子树 → 根节点 → 右子树**。

```
输入: root = [1,null,2,3]
输出: [1,3,2]

    1
     \
      2
     /
    3
```

对上面的树：先访问 1 的左子树（空），再访问 1，再进入右子树 2；2 的左子树是 3，所以先输出 3，再输出 2。

## 思路

### 为什么递归最自然

中序遍历的定义本身就是递归的：

```
inorder(node):
    如果 node 为空，返回
    inorder(node.left)    # 左
    访问 node              # 根
    inorder(node.right)   # 右
```

题目怎么定义，代码就怎么写 —— 这正是递归适合的场景。递归函数不需要思考「栈」这种实现细节，只表达**遍历顺序**。

### 递归的关键：把结果放在哪里

本仓库的实现用了一个外层列表 `stack`，内层函数只负责往里面 `append`：

```python
stack = []
def inorder(root):
    if root == None:return
    inorder(root.left)
    stack.append(root.val)
    inorder(root.right)
inorder(root)
return stack
```

这里 `stack` 虽然叫 stack，但实际扮演的是**结果收集器**（`result` / `res` 更贴切）。递归函数的返回值在这里没有被使用，真正传递结果的是列表的**副作用** —— 三个位置恰好按「左、根、右」的顺序执行 `append`，顺序自然就是中序。

### 迭代写法：用显式栈模拟递归

递归的隐式调用栈，可以改写成显式栈。核心观察：

> 中序遍历要求「一个节点必须等它的**整棵左子树**处理完，才能被访问」。

所以每到一个节点，先一路向左压栈，直到走不动；此时栈顶就是「最左、最该被访问」的节点。弹出并记录后，再转向它的右子树，重复同样的过程。

```python
class Solution(object):
    def inorderTraversal(self, root):
        res, stack = [], []
        cur = root
        while cur or stack:
            while cur:              # 一路向左，把路径压栈
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()       # 弹出最左的节点
            res.append(cur.val)
            cur = cur.right         # 转向右子树
        return res
```

**为什么内层 `while` 结束后弹出的就是答案？** 因为栈里保存的是「从根到当前节点的整条路径」，栈顶永远是路径上最靠左、尚未访问的那个节点。

### 进阶：Morris 遍历（O(1) 空间）

递归和显式栈都需要 O(h) 的额外空间。Morris 遍历利用叶子节点空闲的 `right` 指针，临时把「当前节点的前驱」和「当前节点」连起来，遍历完再恢复，从而把空间降到 O(1)，代价是代码复杂、会临时修改树结构。面试中能说出思路即可，不必优先手写。

## 复杂度

| 写法 | 时间 | 空间 |
|------|:----:|:----:|
| 递归（本仓库） | O(n) | O(h)，递归栈 |
| 显式栈 | O(n) | O(h) |
| Morris | O(n) | **O(1)** |

- `n` 是节点数，每个节点恰好访问一次
- `h` 是树高：平衡树 O(log n)，退化成链表时 O(n)

## 代码

```python
class Solution(object):

    def inorderTraversal(self, root):
        """
        :type root: Optional[TreeNode]
        :rtype: List[int]
        """
        stack = []
        def inorder(root):
            if root == None:return
            inorder(root.left)
            stack.append(root.val)
            inorder(root.right)
            return stack
        inorder(root)
        return stack
```

## 易错点

- **遍历顺序记混**：中序是「左 → 根 → 右」。前序是「根 → 左 → 右」（LeetCode 144），后序是「左 → 右 → 根」（LeetCode 145）。三者只差「访问根」这一行的位置。
- **空树**：`root = null` 时必须返回 `[]`。本实现的 `if root == None: return` 直接兜住，外层返回空列表，正确。
- **把 `append` 放错位置**：放到两次递归之前就是前序，放到之后就是后序。这是三序遍历最本质的区别。
- **内层函数的返回值是多余的**：`return stack` 并不会被外层使用，真正起作用的是 `append` 的副作用。去掉它不影响结果；保留也无害，但容易让人误以为结果靠返回值传递。
- **`stack` 的命名**：这里装的是遍历结果，不是待处理节点。建议改名为 `res`，避免和迭代写法里的真栈混淆。
- **对同一个实例重复调用**：`stack` 是方法内的局部变量，每次调用都会新建，不会跨调用累积。若把它写成 `self.stack`，就会踩到重复调用的坑。
- **递归深度**：LeetCode 94 的节点数有限，Python 默认递归深度足够。若数据规模达到 10⁵ 且树退化成链，需要改迭代写法。

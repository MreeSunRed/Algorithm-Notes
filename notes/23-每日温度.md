# 每日温度 (Daily Temperatures)

> LeetCode 739 · 难度：中等 · 标签：数组、栈、单调栈

## 题目

给定一个整数数组 `temperatures`，表示每天的温度。返回一个数组 `answer`，其中 `answer[i]` 是指对于第 `i` 天，**下一个更高温度**出现在几天后。如果气温在这之后都不会升高，该位置用 `0` 来代替。

```
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]

输入: temperatures = [30,40,50,60]
输出: [1,1,1,0]
```

## 思路

### 暴力解

对每一天 `i`，向后扫描找到第一个比它大的温度，距离就是答案。

- 时间 O(n²)，最坏情况（温度递减）每天都要扫到末尾
- 空间 O(1)

### 单调栈

换一个方向思考：不要「对每天往后找」，而是**每遇到一个新温度，就回头结算所有还没找到更高温的日子**。

维护一个栈，里面存的是**还没有被解答的下标**。关键性质：

> 栈中下标对应的温度，从栈底到栈顶是**非递增**的。

为什么？如果新来的温度比栈顶高，栈顶就已经被解答、会被弹掉；能留在栈里的，一定是从某个较热的日子开始一路不升的温度序列。

处理第 `i` 天时：

1. 只要栈非空且「栈顶那天的温度 < 今天的温度」，说明今天就是栈顶那天的答案
2. 弹出栈顶下标 `j`，填 `res[j] = i - j`
3. 重复直到栈顶温度不小于今天，或栈空
4. 把今天的下标 `i` 压栈

**为什么用 while 而不是 if？** 今天的高温可能同时解答前面好几天。例如 `[70,60,50,80]`，第 4 天 80 会依次解答 50、60、70 三天。

**为什么栈里存下标而不是温度？** 答案需要的是「相隔几天」，只有下标才能算出 `i - j`；温度可以从 `temperatures[j]` 随时取。

### 例子走一遍

以 `[73,74,75,71,69,72,76,73]` 为例：

| i | 温度 | 弹栈与填值 | 栈（存下标） |
|:-:|:----:|------------|--------------|
| 0 | 73 | — | `[0]` |
| 1 | 74 | 弹 0，res[0]=1 | `[1]` |
| 2 | 75 | 弹 1，res[1]=1 | `[2]` |
| 3 | 71 | — | `[2,3]` |
| 4 | 69 | — | `[2,3,4]` |
| 5 | 72 | 弹 4→1，弹 3→2 | `[2,5]` |
| 6 | 76 | 弹 5→1，弹 2→4 | `[6]` |
| 7 | 73 | — | `[6,7]` |

最终 `[1,1,4,2,1,1,0,0]`，剩下没被弹掉的下标保持初始值 0，表示之后没有更高温。

## 复杂度

- **时间 O(n)**：每个下标最多入栈一次、出栈一次，while 循环的总执行次数不超过 n
- **空间 O(n)**：栈最多存下所有下标（温度单调递减时）

## 代码

```python
class Solution(object):
    def dailyTemperatures(self, temperatures):
        """
        :type temperatures: List[int]
        :rtype: List[int]
        """
        res = [0] * len(temperatures)
        s = []
        for i, t in enumerate(temperatures):
            while s and temperatures[s[-1]] < t:
                j = s.pop()
                res[j] = i - j
            s.append(i)
        return res
```

## 易错点

- **`s.pop` 少了括号（原代码的真实 bug）**：`j = s.pop` 拿到的是**绑定方法对象**，不是弹出的下标；随后 `res[j]` 会抛 `TypeError: list indices must be integers or slices, not builtin_function_or_method`。必须写 `s.pop()`。这个错误在「永远没有更高温」的输入上不会触发，只有出现升温才会暴露，测试里的普通用例就能抓到。
- **比较用 `<` 而不是 `<=`**：题目要求**更高**的温度，温度相等不算。用 `<=` 会把等温的天误判为答案。
- **栈里存温度而不是下标**：存温度无法计算「几天后」，答案需要的是下标差。
- **`while` 写成 `if`**：一天的高温可能连续解答多个历史日子，只处理一次会漏掉部分答案。
- **初始值**：结果数组初始化为 0，恰好表示「之后没有更高温」，不需要额外填充。
- **`i - j` 的方向**：`i` 是今天、`j` 是历史某天，距离是 `i - j`，不要写反。
- **空数组**：LeetCode 保证 `1 <= temperatures.length`；若允许空数组，本实现返回 `[]`，也正确。
- **单元素**：栈中只有它，没有机会被弹出，返回 `[0]`。
- **温度相等**：`[73,73,73]` 全部返回 0，因为不存在**严格更高**的温度。

| 输入 | 输出 | 说明 |
|------|------|------|
| `[73,74,75,71,69,72,76,73]` | `[1,1,4,2,1,1,0,0]` | 经典用例，含连续弹栈 |

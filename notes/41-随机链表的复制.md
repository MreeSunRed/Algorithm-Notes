# 随机链表的复制 (Copy List with Random Pointer)

> LeetCode 138 · 难度：中等 · 标签：链表、哈希表

## 题目

给你一个长度为 `n` 的链表，每个节点除了 `next` 指针外，还包含一个 `random` 指针，它可以指向链表中的任意节点或空节点。

请构造这个链表的**深拷贝**：新链表由 `n` 个全新节点组成，节点的值与原节点相同，`next` 和 `random` 指针都要指向**复制链表中的新节点**，不能指向原链表节点。

```
输入: head = [[7,null],[13,0],[11,4],[10,2],[1,0]]
输出: [[7,null],[13,0],[11,4],[10,2],[1,0]]

输入: head = []
输出: []
```

每个 `[val, random_index]` 中，`random_index` 是 `random` 指向节点的下标，`null` 表示指向空。

## 思路

### 难点在哪

普通的链表复制只需要顺着 `next` 走一遍，创建一个新节点接一个即可。但 `random` 可以指向**还没创建出来的节点**（例如第 0 个节点的 `random` 指向第 4 个节点），所以不能一边建链表一边直接连 `random`。

### 本仓库实现：哈希表 + 两趟遍历

第一趟：顺着 `next` 创建所有新节点，同时用字典记录「原节点 → 新节点」的映射。

```python
node_map[old] = new_node
```

第二趟：再遍历一遍，把每个新节点的 `random` 从「指向原节点」替换成「指向对应的新节点」。

```python
new.random = node_map[new.random]
```

实现里有一个小技巧：第一趟创建节点时先把 `new_node.random = old.random` 临时存下来，第二趟拿这个旧指针去字典里查新指针，就不需要额外保存原链表节点了。

以 `[[7,null],[13,0],[11,4],[10,2],[1,0]]` 为例：

| 下标 | 值 | random 下标 | 第一趟后 | 第二趟修正 random |
|:---:|:--:|:-----------:|----------|-------------------|
| 0 | 7 | null | `new0` 的 random 暂存 `None` | `None` |
| 1 | 13 | 0 | `new1` 的 random 暂存 `old0` | `new0` |
| 2 | 11 | 4 | `new2` 的 random 暂存 `old4` | `new4` |
| 3 | 10 | 2 | `new3` 的 random 暂存 `old2` | `new2` |
| 4 | 1 | 0 | `new4` 的 random 暂存 `old0` | `new0` |

两趟都只扫一遍链表，总时间 O(n)，字典额外存 n 项，空间 O(n)。

### 其他写法

- **递归 + 记忆化**：`copy(node)` 先从字典查是否已复制；没有就创建新节点并登记，再递归复制 `next` 和 `random`。本质与哈希表两趟相同。
- **O(1) 额外空间的穿插法**：
  1. 把每个新节点插到原节点后面：`A → A' → B → B' → ...`
  2. 令 `A'.random = A.random.next`（原 random 的后一个就是它的副本）
  3. 把 `next` 拆成原链表和新链表两条

  思路巧妙，但指针操作多、容易写错；工程上哈希表写法更直观。

## 复杂度

- **时间 O(n)**：两趟遍历，字典查询/插入均摊 O(1)
- **空间 O(n)**：哈希表保存 n 组原节点到新节点的映射；递归写法还有 O(n) 递归栈

## 代码

```python
# Definition for a Node.
class Node:
    def __init__(self, x, next=None, random=None):
        self.val = int(x)
        self.next = next
        self.random = random


class Solution(object):
    def copyRandomList(self, head):
        """
        :type head: Node
        :rtype: Node
        """
        old = head
        copyhead = Node(0)
        new = copyhead
        node_map = {}
        while old is not None:
            new_node = Node(x=old.val, random=old.random)
            new.next = new_node
            new = new_node
            node_map[old] = new_node
            old = old.next
        copyhead = copyhead.next
        new = copyhead
        while new is not None:
            if new.random is not None:
                new.random = node_map[new.random]
            else:
                new.random = None
            new = new.next
        return copyhead
```

## 易错点

- **只复制 `next`，`random` 仍指向原节点**：这不是深拷贝，原链表释放后 `random` 就成了悬空指针，也违反题目要求。
- **一遍建链表时直接连 `random`**：`random` 可能指向尚未创建的节点，此时字典里查不到，会抛 `KeyError`。必须先建完所有节点。
- **`random` 为 `None` 时直接查字典**：`node_map[None]` 会抛 `KeyError`，必须单独判断。
- **第二趟遍历错对象**：要遍历新链表，并用新节点暂存的旧 `random` 去查映射；遍历原链表再用原节点改 `random` 会修改原数据。
- **复用原节点**：`new_node = old` 只是别名，不是复制，两个链表会共享节点。
- **用节点的值做字典键**：值可能重复，必须用节点对象（默认按身份比较）作为键。
- **重写 `__eq__` / `__hash__`**：如果 Node 重写了相等语义，字典可能把两个不同的节点当成同一个键；本题的 Node 没有重写，默认识别对象身份，正好适用。
- **空链表**：`copyhead.next` 为 `None`，直接返回 `None`，不要返回哑节点。
- **单节点自环 `random`**：`node_map[node]` 就是它自己的副本，能正确指向新节点本身。
- **哑节点的 `random`**：哑节点只用来简化尾插，不参与结果，第二趟从 `copyhead.next` 开始即可。

## 边界测试

| 输入 | 输出 | 说明 |
|------|------|------|
| `[]` | `[]` | 空链表 |
| `[[7,null]]` | `[[7,null]]` | 单节点，random 为空 |
| `[[7,0]]` | `[[7,0]]` | 单节点，random 指向自己 |
| `[[1,None],[2,None]]` | 同左 | 所有 random 均为空 |
| `[[7,null],[13,0],[11,4],[10,2],[1,0]]` | 同左 | LeetCode 经典用例，random 前后交叉 |
| `[[1,2],[1,1],[1,0]]` | 同左 | 值全部相同，验证按节点身份映射而非按值 |
| 非空任意链表 | 结构与值相同 | 新链表所有节点都不能与原链表共享 |

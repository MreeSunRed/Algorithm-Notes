# 合并区间 (Merge Intervals)

> LeetCode 56 · 难度：中等 · 标签：数组、排序

## 题目

以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [start_i, end_i]`。请你合并所有重叠的区间，并返回**一个不重叠的区间数组**，该数组需恰好覆盖输入中的所有区间。

```
输入: intervals = [[1,3],[2,6],[8,10],[15,18]]
输出: [[1,6],[8,10],[15,18]]
解释: 区间 [1,3] 和 [2,6] 重叠, 将它们合并为 [1,6].
```

## 思路

### 暴力解

反复扫描所有区间对，发现重叠就合并，直到一轮扫描没有任何合并为止。

- 每轮 O(n²) 判重叠，最坏需要 O(n) 轮 → O(n³)
- 即使实现得更好，也至少是 O(n²)

暴力的浪费在于：重叠关系是**无序**的，两个该合并的区间可能隔着很远，只能反复回头找。

### 关键一步：排序

把所有区间按**左端点**升序排序。排序之后，一个重要的性质出现了：

> 如果区间 A 排在区间 B 前面，那么能合并的区间一定在排序后**相邻地浮现**出来。

因为 A 的左端点不超过 B 的左端点，一旦发现某个区间的左端点**大于当前合并区间的右端点**，就可以断定：它和它后面的所有区间，都不会再和当前区间重叠（后面的左端点只会更大）。

**排序把「全局找重叠」变成了「顺序看邻居」**，这是整道题的转折点。

### 一次遍历

维护一个结果列表 `res`，并保证 `res[-1]` 是「已处理区间合并后的最后一个区间」：

| 情况 | 动作 |
|------|------|
| 新区间 `start <= res[-1].end` | 有重叠（含端点相接），把 `res[-1].end` 更新为 `max(原 end, 新区间 end)` |
| 新区间 `start > res[-1].end` | 不重叠，直接追加到 `res` |

**为什么更新 end 要用 `max`？**

反例：`[[1,10], [2,3]]`。第二个区间完全被第一个包住，若直接写 `end = 3`，答案会缩水成 `[1,3]`。必须取两者较大值。

### 本仓库的实现：排序 + 双重扫描

代码同样先排序，但对每个起点 `i`，用内层 `j` 从头扫到尾寻找可合并的区间，并用 `i = j` 跳过已合并的部分：

```python
intervals.sort()
while i < len(intervals):
    temp = [intervals[i][0], intervals[i][1]]
    j = i
    while j < len(intervals):
        val2 = intervals[j]
        if temp[1] >= val2[0] and temp[1] <= val2[1] or val2[1] <= temp[1]:
            temp[1] = max(val2[1], temp[1])
            i = j
        j += 1
    res.append(temp)
    i += 1
```

**它是对的，但内层循环是多余的。** 排序后左端点已经递增，设当前合并区间为 `[start, end]`、下一个区间为 `[s, e]`，必有 `s >= start`：

- 若 `end >= s`：两者重叠，新 end 为 `max(end, e)`
- 若 `end < s`：后面的所有区间左端点都 `>= s > end`，不可能再重叠

所以条件里那串 `temp[1] >= val2[0] and temp[1] <= val2[1] or val2[1] <= temp[1]`，在排序前提下其实就等价于 `temp[1] >= val2[0]`；而「不重叠就继续往后扫」也永远扫不出东西。内层循环可以整个删掉。

### 最优写法：一次遍历

```python
class Solution(object):
    def merge(self, intervals):
        intervals.sort(key=lambda x: x[0])
        res = []
        for start, end in intervals:
            if res and start <= res[-1][1]:
                res[-1][1] = max(res[-1][1], end)
            else:
                res.append([start, end])
        return res
```

## 复杂度

| 写法 | 时间 | 空间 |
|------|:----:|:----:|
| 本仓库实现（双重扫描） | O(n²) 最坏 | O(n) |
| 排序 + 一次遍历 | **O(n log n)** | O(n)（结果数组） |

- **时间**：排序 O(n log n) 是瓶颈；一次遍历 O(n)。本仓库实现里，若区间互不重叠（如 `[[1,2],[3,4],[5,6],…]`），内层循环每个 `i` 都要扫到末尾，退化为 O(n²)。
- **空间**：结果数组 O(n)；Python 的 `sort()` 原地排序，额外空间取决于 Timsort 实现（最坏 O(n)）。若不允许修改输入，需先拷贝一份。

## 代码

```python
class Solution(object):
    def merge(self, intervals):
        """
        :type intervals: List[List[int]]
        :rtype: List[List[int]]
        """
        res = []
        i = 0
        intervals.sort()
        while i < len(intervals):
            val1 = intervals[i]
            temp = [val1[0], val1[1]]
            j = i
            while j < len(intervals):
                val2 = intervals[j]
                if temp[1] >= val2[0] and temp[1] <= val2[1] or val2[1] <= temp[1]:
                    temp[1] = max(val2[1], temp[1])
                    i = j
                j += 1
            res.append([temp[0], temp[1]])
            i += 1
        return res
```

## 易错点

- **忘记排序**：不排序直接合并，需要反复回溯，既慢又容易漏。排序是这道题的前提。
- **end 不取 `max`**：`[[1,10],[2,3]]` 会得到 `[1,3]`。被完全包含的区间必须用 `max` 保住原来的右端点。
- **端点相接算重叠**：`[[1,4],[4,5]]` 应合并为 `[1,5]`（题目中的「重叠」包含端点接触）。判断用 `<=` 而不是 `<`。
- **`and` / `or` 的优先级**：`and` 比 `or` 先结合，原条件等价于 `(A and B) or C`。虽然结果碰巧正确，但可读性差，建议加括号或直接简化为 `temp[1] >= val2[0]`。
- **`i = j` 之后还要 `i += 1`**：`j` 指向最后一个已合并的区间，下一轮必须从它后面开始，否则会重复处理。本实现两处都写了，顺序正确。
- **原地排序修改输入**：`intervals.sort()` 会改变调用方传入的列表。LeetCode 不介意；若在真实项目里不想改输入，先 `sorted(intervals)` 拷贝。
- **空输入**：`intervals = []` 时，排序和循环都不执行，直接返回 `[]`，本实现天然正确。
- **返回值类型**：必须是 `List[List[int]]`，别返回元组列表或共享同一个内部列表（每次 `append` 都应新建对象）。

|------|------|------|
| `[[1,3],[2,6],[8,10],[15,18]]` | `[[1,6],[8,10],[15,18]]` | 经典用例 |
